# UPSTDC Database (PostgreSQL)

This directory contains the PostgreSQL schema and seed data for the UPSTDC Infrastructure Monitoring system. Migrations are Flyway-compatible and create all core tables, constraints, indexes, and initial data.

## Contents

- migrations/
  - V1__init.sql — Full normalized schema (RBAC, Projects, Tenders, Contractors, Funds, Milestones, Project Progress, Inspections, Handovers, Payments, Documents, Audit Logs)
  - V2__seed_roles_users.sql — Seeds roles, essential permissions, role-permission mappings, and a default admin user with placeholder password
- startup.sh — Minimal PostgreSQL startup (used in some environments)
- db_connection.txt — Saved connection string (generated by startup.sh)
- db_visualizer/ — Simple DB viewer service (optional)

## Connection and Port

- The target PostgreSQL instance is expected to run on port 5001.
- Example connection URL:
  postgresql://appuser:dbuser123@localhost:5001/myapp

If you used the included startup.sh previously, it defaults to port 5000. For Flyway/tests here, use port 5001. To keep this change minimal, we do not modify the startup.sh now; instead update your environment variables and Flyway configuration to point to port 5001.

## Applying Migrations (Flyway)

Ensure you have Flyway installed or use the Flyway Docker image.

Environment variables (example):
- FLYWAY_URL=jdbc:postgresql://localhost:5001/myapp
- FLYWAY_USER=appuser
- FLYWAY_PASSWORD=dbuser123
- FLYWAY_SCHEMAS=public

Using Docker:
docker run --rm -v "$(pwd)/migrations:/flyway/sql" flyway/flyway:9.22.2 -url=jdbc:postgresql://host.docker.internal:5001/myapp -user=appuser -password=dbuser123 migrate

Using local Flyway CLI:
flyway -url=jdbc:postgresql://localhost:5001/myapp -user=appuser -password=dbuser123 migrate

Directory layout must be:
upstdc_database/
  migrations/
    V1__init.sql
    V2__seed_roles_users.sql

## Default Admin User

- Email: admin@upstdc.in
- Password hash: the literal string 'ADMIN_PASSWORD_HASH' (not usable for login)
- On first backend start, replace this with a real bcrypt hash and force a password reset.

## Notes on Schema

- All primary keys use GENERATED ALWAYS AS IDENTITY (bigint).
- Soft delete columns: is_deleted boolean as applicable.
- Timestamps: created_at default now(), updated_at default now(); application should update updated_at.
- Geo fields (lat/lng): numeric(10,7) for ~1cm precision without requiring PostGIS.
- Documents table is polymorphic: (owner_type, owner_id) pair is indexed; referential constraints enforced by application.

## Minimal Changes to Scripts

We have not modified startup.sh to avoid disrupting existing setups. If you need to use it for local runs, either:
1) Change DB_PORT in startup.sh to 5001 manually before running; or
2) Keep startup.sh as-is (5000) but point Flyway to whatever port your DB is actually running on.

This README serves as the authoritative guide to run migrations against port 5001 as requested.

## Troubleshooting

- Ensure the database and user exist and have privileges on the public schema.
- If using Docker for PostgreSQL, map port 5001 and create the database 'myapp' and user 'appuser' with the specified password.
- For idempotency, seed steps use ON CONFLICT DO NOTHING.
